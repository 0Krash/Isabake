# App Links Setup

Phase 27 makes invitation links production-ready without requiring a real
domain during local development.

## Supported Links

- `isabake://invite/<token>`
- `isabake:///invite/<token>`
- `https://<configured-domain>/invite/<token>`

Opening an invitation link only routes to the invitation screen. It must not
force login, run sync, start dev diagnostics, or connect sockets.

## Required Env Vars

Mobile Expo config:

```sh
EXPO_PUBLIC_INVITE_DOMAIN=links.example.com
```

Backend email/link generation:

```sh
APP_INVITE_BASE_URL=https://links.example.com/invite
```

`EXPO_PUBLIC_INVITE_DOMAIN` controls native app-link association in the Expo
build. `APP_INVITE_BASE_URL` controls the invite link generated by the backend
and sent through the email provider.

For local development, both can be empty. The backend falls back to
`isabake://invite/<token>`.

## Expo Native Config

When `EXPO_PUBLIC_INVITE_DOMAIN` is set, `UI/app.config.js` adds:

- Android `intentFilters` for `https://<domain>/invite/*`
- iOS `associatedDomains` with `applinks:<domain>`
- custom scheme remains `isabake`

When no domain is set, the local Expo config remains unchanged apart from the
existing custom scheme.

## Android Domain File

Host this file at:

```text
https://<domain>/.well-known/assetlinks.json
```

Use `docs/app-links/android-assetlinks.template.json` and replace:

- `REPLACE_WITH_ANDROID_PACKAGE`
- `REPLACE_WITH_RELEASE_SHA256_CERT_FINGERPRINT`

Current Expo Android package in `UI/app.json` is:

```text
com.anonymous.UI
```

Confirm or replace it before production release.

## iOS Domain File

Host this file at:

```text
https://<domain>/.well-known/apple-app-site-association
```

Use `docs/app-links/apple-app-site-association.template.json` and replace:

- `REPLACE_WITH_TEAM_ID`
- `REPLACE_WITH_IOS_BUNDLE_IDENTIFIER`

The final file must be served as JSON with no `.json` extension in the URL.
The iOS bundle identifier is not currently configured in `UI/app.json`; add the
production bundle identifier before release.

## Dev Test Commands

Custom scheme:

```sh
npx uri-scheme open "isabake://invite/dev_token" --ios
npx uri-scheme open "isabake://invite/dev_token" --android
npx uri-scheme open "isabake:///invite/dev_token" --ios
npx uri-scheme open "isabake:///invite/dev_token" --android
```

Production HTTPS links after native build and domain association:

```sh
npx uri-scheme open "https://links.example.com/invite/dev_token?utm=email" --ios
npx uri-scheme open "https://links.example.com/invite/dev_token?utm=email" --android
```

## Production Checklist

- Set `EXPO_PUBLIC_INVITE_DOMAIN`.
- Set `APP_INVITE_BASE_URL=https://<domain>/invite`.
- Set a final Android package name.
- Set a final iOS bundle identifier.
- Host `/.well-known/assetlinks.json`.
- Host `/.well-known/apple-app-site-association`.
- Build native apps after env changes.
- Verify invite links open `InvitationAcceptScreen`.
- Verify accepting an invitation does not run push/pull/full sync.
- Verify normal UI does not show raw invite tokens or hashes.

## Pending Until Real Domain Exists
